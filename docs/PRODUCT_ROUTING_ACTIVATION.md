# Official single-number product routing

This increment activates the existing durable product router for MusicScale, NestFinance and NestJourney. It runs only after signed Meta ingestion has durably stored canonical inbound evidence, within the existing24-hour service window. Explicit product/signed origin and persistent context determine the product; ambiguity or a conflicting known MusicScale intent asks for clarification instead of silently changing scope.

The router does not grant identity or domain permissions. MusicScale supported reads still use existing Hub/channel identity and Tool Gateway authorization. NestFinance, NestJourney and unsupported requests enter human review; no domain integration is fabricated. Optional product owners are validated as bounded IDs and must still pass the canonical operator directory before assignment. Missing/unavailable owners leave an actual unassigned human-review queue. Human-owned conversations are never taken over.

Activation requires all three explicit routing flags, a valid existing origin signing secret, current private storage evidence and ACTIVE expiresAt TTL. The release reads the actual published Rules and requires the exact SHA256 previously tested by Hub privacy gate38576220130 (156 browser denial checks), then reads current connectProductRoutes TTL. It changes no Rules, TTL configuration, IAM, Meta credentials/number/webhook or billing. If the published Rules fingerprint changes, stop before deployment and rerun the existing published-Rules privacy test; do not merely replace the approved fingerprint.

The new revision is deployed without general traffic before the exact revision gate. Direct and canonical health must report both requested=true and mounted=true for productRouting, in addition to the exact release SHA. A flag alone is never readiness. Existing traffic/Hosting recovery is retained. Real push remains disabled/test-mode, and automation execution and Finance data tool flags remain disabled.

Tests cover the existing router's durable deduplication, replay/Meta window, context/product switching, tenant evidence, verified owner/fallback and human control, plus strict owner parsing, conflict clarification, actual server mount prerequisites and credential-free health. The storage probe is tested against synthetic approved/tampered Rules, active/inactive TTL, foreign references/project and provider failures, with only GET operations. Positive actual-account Meta conversations and physical phone delivery remain separate homologation evidence, not established by a successful deployment.
