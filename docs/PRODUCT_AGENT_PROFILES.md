# Product support profiles

MusicScale, NestFinance and NestJourney have separate server-owned communication styles, curated PT/EN/ES public knowledge, official app links and entry/help responses. Supported domain tool references come from the existing product/tool registry; this adds no grants or domain business rules. Product owners use the existing validated configuration and canonical operator directory. Missing/unverified owners remain unassigned for human review.

These profiles execute deterministic public support knowledge, with no generative model or model spend. They handle the standard manually submitted support draft, basic product overview/access/capability questions, and ask for the next user question. They never echo user input or read a private record. Sensitive/personal/financial/pastoral requests and explicit human requests continue to the existing authorized tool flow or actual human queue. Supported MusicScale tools retain priority and fresh canonical authorization. Unsupported media is queued for human review without reading or echoing its content. Existing human-owned/paused conversation control, stored evidence,24-hour Meta window, durable reply idempotency and per-tenant context remain enforced by the existing router and dispatch service.

`GET /api/core/agents/product-profiles?organizationId=...` requires fresh Hub-resolved organization equality and existing Connect Inbox manage authority. It returns public profile knowledge/tool bounds and an owner UID only after current same-organization directory verification. Provider failures cannot expose owner configuration or response bodies. No mutation endpoint or editable per-tenant knowledge is claimed; configuration comes from server defaults plus existing product owners. No new storage/Rules/IAM or paid service is introduced.

Actual app event publishers, reminders/follow-ups, editable per-organization agent customization, generative AI and missing Finance/Journey domain capabilities remain separate unfinished work. Automated fixtures and deployment401 gates do not certify real-account Meta conversations or physical iPhone notifications.

## Live manager screen

The Agents route now reads the mounted canonical manager endpoint using the current transient session bearer. It shows each product’s curated public knowledge, welcome message, style, available query count and verified-owner or real human-queue state in PT/EN/ES. It never renders raw owner IDs or provider bodies. Requests are cancelled on session change/unmount, time out after ten seconds, and previous-session results are hidden synchronously. Forbidden, expired-session and unavailable responses have separate states and a manual retry. No profile editing or outbound test send is claimed.

## Exact Hosting publication gate

The official Core release now generates strict public SHA metadata for the actual built HTML, JavaScript, CSS and authentication entry script. Before a release passes, both default and canonical Hosting domains must serve the same metadata, exact HTML and matching asset bytes. Expected hashes are anchored in the local build manifest, never defined by the serving domain: even self-consistent forged remote metadata fails. HTML SPA fallbacks, stale CDN content and mismatched versions fail a bounded retry gate and retain existing failed-release recovery. This proves artifact publication, not authenticated business flows or physical device delivery.
