# Organization-owned support settings

Connect supports server-owned profiles at `organizations/{orgId}/connectAgentProfiles/{musicscale|nestfinance|nestjourney}`. The existing Agents page can explicitly save enabled state, communication style, a current authorized support owner and public overview/welcome text in PT/EN/ES. All six text fields are required, bounded to 1,200 characters and plain text without links; the immutable official app URL is appended by Connect. A separate explicit public-content confirmation is required on each edit. Never enter personal/financial records or credentials. This is curated deterministic support, not generative AI or domain automation.

GET `/api/core/agents/product-profiles?organizationId=...` revalidates canonical Hub management authority, reads the three scoped records and verifies configured owners. Missing records retain existing defaults. Storage failures return a generic503; they never silently restore defaults. Domain permissions, tools, URLs, identity and billing cannot be configured here. Communication style selects only deterministic phrasing, not a model. Private questions continue through canonical supported tools or the actual human queue.

PUT `/api/core/agents/product-profiles/:product?organizationId=...` requires the same fresh authority and exactly `{expectedVersion,requestId,publicKnowledgeConfirmed:true,settings:{enabled,communicationStyle,ownerUid,overview,intake}}`. The backend checks an assigned owner against the current same-organization Hub directory. Browser UIDs/permissions/tenant claims in the body are rejected. Responses contain only success, matching scope, version and replay state; provider details and tokens are never returned or recorded.

Each write compares the loaded version and Firestore updateTime atomically. Version0 creates only a missing document; no delete or blind overwrite exists. A retained request ID accepts only the identical actor/payload/current revision; changed or superseded requests conflict409 and require a refresh. The latest20 audit revisions contain time, version, request ID, tenant-scoped actor hash and payload hash, without previous knowledge text or bearer. No collection scan, background model cost, new index or TTL is needed.

Each persisted record also requires a tenant/product-bound HMAC under a separate domain prefix using the existing server-only support-origin root. This does not change that root or Meta credentials. Unsigned records that might predate the private Rules, or later modified records, fail closed instead of becoming approved agent knowledge. The MAC/root is not accepted from the browser or returned by the profile API. Rotation must retain read compatibility or pause routing until records are explicitly reapproved; never silently restore defaults.

The real WhatsApp router reads settings after durable signed inbound ingestion and before public replies or private MusicScale forwarding. Disabled agents enter human support; configured owners are reverified before assignment. Unavailable settings queue the inbound for review without an automatic answer. Existing human control, evidence, Meta service-window and deduplication checks are preserved. The UI aborts pending requests on unmount, isolates session results, uses explicit saves, preserves request IDs for transport retries and refuses stale revision edits. Owner-directory failures cannot authorize another assignee.

Activation requires `CONNECT_PRODUCT_AGENT_SETTINGS_ENABLED=true` and `CONNECT_PRODUCT_AGENT_SETTINGS_PRIVATE_CONFIRMED=true`, alongside existing routing prerequisites. Editing additionally requires `CONNECT_PRODUCT_AGENT_SETTINGS_EDITING_ENABLED=true`. Requesting settings without confirmed storage prevents router activation. Before enabling, require successful Hub emulator gates, official Rules publication and a read-only test of the actual published source; update Connect's exact approved Rules fingerprint from that evidence. Never remove the fingerprint gate. Until these release gates pass, all settings flags remain unset/off.

Deploy the settings reader/router enforcement first with editing explicitlyfalse: GET remains management-protected; PUT404 and hidden editor prevent new configuration writes. Verify the exact serving Core/frontend SHA and keep that reader revision as rollback target. Only a subsequent gated release enables editing (PUT401 without identity). A rollback to the verified reader then preserves disabled agents and current signed settings. Do not roll back to a pre-reader revision or pre-privacy Rules after settings exist; pause routing if such recovery is required. Existing official traffic/Hosting rollback remains in place.

Validation covers strict fields, immutable tool authority, fresh Hub/tenant/owner checks, Firestore create/update preconditions, masked bounded audit, idempotent retries, superseded edits, storage/provider failure, scoped client DTOs, disabled-agent/private forwarding and actual human fallback. Local TypeScript/builds and HTTP composition were executed. Positive real-account manager/browser/Meta flows and physical iPhone delivery require separate evidence; these tests do not certify them.
