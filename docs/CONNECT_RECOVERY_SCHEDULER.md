# Low-cost periodic internal recovery (fallback from GCP Scheduler)

**Proven blocker 2026-10-15:** Production workflow [38798802527](https://github.com/prdanielcunha/millionsnest-connect/actions/runs/38798802527) stopped with `RECOVERY_BLOCKED_CLOUD_SCHEDULER_API_NOT_ENABLED`. No recurring service was activated and the script did not enable/change billing. Cloud Run and Inbox continued serving the previously proven `4ba5e6f8fec95937ccdc5d6d581c4d4ab2d78107`.

The revised production script provisions a pinned one-task Cloud Run Job with the **existing** Connect HMAC recovery executable and Secret Manager mount, and proves one real signed execution before claiming the job works. It does not create a Cloud Scheduler resource or enable an API.

Periodic invocation is delegated to [`.github/workflows/connect-hourly-internal-recovery.yml`](../.github/workflows/connect-hourly-internal-recovery.yml) on the **default branch `main`**: every hour at UTC minute 17 it obtains short-lived GitHub OIDC/GCP credentials, checks the actual canonical serving SHA and queue-only flags, verifies the pre-provisioned Cloud Run Job image, then executes **one** signed bounded job with no automatic reattempt on ambiguous execution. It never obtains or logs HMAC credentials. No secrets or Meta configuration change is allowed. Avoid paid Cloud Scheduler configuration.

**Honest reliability boundary:** GitHub-hosted cron can run late or be skipped at high load; it is a zero/low-cost **best-effort recurring invoker**, not a guaranteed interval or guaranteed alert delivery. The next cron run must be verified in Actions before claiming unattended recovery operational. Missed cycles remain durable in the existing outbox for later catch-up. The job batch is capped and stores human-review failures. Monitor failed runs and age of pending jobs; for strict SLAs, formally approve Cloud Scheduler or an equivalent managed trigger with billing assessment.

To halt periodic recovery without losing data, disable the named GitHub workflow. No customer messages, jobs, budgets, Hub identity, Meta settings or subscriptions are removed. Push remains OFF, broad automations OFF, Meta templates OFF, and the physical iPhone test remains mandatory before any real push.
